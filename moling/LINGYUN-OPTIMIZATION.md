# 灵云算码

通用流程见 `HOWTO-OPTIMIZATION.md`。本文记录灵云自己的文件、编码规则、字集和字频。命令都在 `moling/` 目录下执行。`SCHEMA=lingyun`。

## 1. 文件

| 用途 | 文件 |
|---|---|
| 退火配置 | `config-lingyun.toml` |
| 键位分布 | `key_distribution-lingyun.txt` |
| 方案默认值 | `init.sh` 的 `lingyun` 分支 |
| 输入准备入口 | `prepare-inputs.sh` |
| 优化入口 | `optimize.sh` |
| 输出目录 | `lingyun-output/output-<时间戳>/` |
| 算码字符集 | `chars.txt`，由 `yuhao_charsets.lua` 按现有流程生成 |
| 字根集合参考 | `roots-moqing.txt` |
| 字根聚类参考 | `roots-cluster-moqing.txt`，其聚类来自卿云 |
| 字根首笔数据 | `yuhao-zigens.csv` |
| 汉字结构数据 | `~/home/IDS/babelstone/IDS.TXT` |
| 结构解析辅助脚本 | `prepare-lingyun-structures.py` |
| 生成的结构分类 | `structures-lingyun.tsv` |
| 生成的 IDS 分歧清单 | `structure-conflicts-lingyun.tsv` |
| 四定词编码脚本 | `generate-lingyun-words-dict.pl` |

`key_distribution.txt` 是魔灵和未单独配置键位文件的方案用的。灵云应使用自己的配置和键位分布文件。

`pair_equivalence.txt` 沿用现有陈氏键对当量表。灵云的优化参数和验收目标另行设定，不照搬潇明或魔卿的历史目标。

输入准备沿用公共流程，生成共享的 `input-fixed.txt`、`input-roots.txt` 和 `input-division.txt`。切换方案后须重新准备输入，不能直接复用上一方案的输入文件。`optimize.sh` 默认会重新准备，并在准备完成后备份本次实际输入。

灵云的备份包含实际复用的 `roots-moqing.txt`、`roots-cluster-moqing.txt`，以及结构解析脚本、结构分类和分歧清单。

## 2. 方案规则

### 2.1 字根与键位

复用卿云字根，采用纯乱序：

- 大码保留卿云的形近字根聚类，同组字根共用大码，在允许键位中由优化分配。
- 小码逐根独立乱序，不按声母分组，也不跟随大码聚类。
- 大码共 19 键：`qwrtyuopasghlxcvbnm`，即排除 `edfijkz`。
- 小码共 20 键：`qwrtyuopasghlzxcvbnm`，即大码的 19 键加 `z`。
- B 区为 `edfijk`，用于首笔补码和简码。
- 大码不使用 `z`，小码可以使用 `z`。

沿用的是字根聚类关系，不沿用已有布局的固定大码键位、声母小码或高频根键位限制。

### 2.2 六笔画补码

补码取字根的**首笔**，沿用 `yuhao-zigens.csv` 的六笔画 `1–6` 分类，区分两类折笔。相同首笔类别的字根共用补码，六类分别作为一个优化分组，由退火算法在 `edfijk` 中分配键位。

不预设类别与键位的固定对应。约束沿用现有脚本的分组优化方式，不同类别可以分配到同一键；各类的最终补码以本次优化得到的字根键位表为准。固定 B 简仍为「我 e、的 d、是 f、有 i、在 j、你 k」，不随笔画补码的优化改变。

下文“末根补码”均指末根的首笔补码，不是末根的末笔。

沿用 `prepare-inputs.sh` 现有首笔纠错，包括解决同一字根在 CSV 中的首笔冲突。例如「乙」取 5、「山」取 2、「水」取 2、「卯」取 3；`USE_STROKE_5_FOR_6=0`，不合并两类折笔。

### 2.3 单字全码

最大码长为四码。下表的 `A/B` 表示键区：大码、小码落在 A 区，首笔补码落在 B 区；具体取哪个字根、哪个码位，以“取码顺序”为准。

| 字根数 | 汉字结构 | 取码顺序 | 码型 |
|---|---|---|---|
| 1 | 所有结构 | 字根大码＋字根小码＋字根首笔补码 | `AAB` |
| 2 | 左右／左中右 | 首根大码＋末根大码＋末根小码＋末根首笔补码 | `AAAB` |
| 3 | 左右／左中右 | 首根大码＋次根大码＋末根大码＋末根小码 | `AAAA` |
| 2 | 其他结构 | 首根大码＋末根大码＋末根首笔补码 | `AAB` |
| 3 | 其他结构 | 首根大码＋次根大码＋末根大码＋末根首笔补码 | `AAAB` |
| 4 及以上 | 所有结构 | 首根大码＋次根大码＋第三根大码＋末根大码 | `AAAA` |

字根数和取根顺序沿用现有宇码拆分流程。单根字、多根字均按上表处理，不使用灵明跳根、魔灵回头码或潇明的取码规则。

### 2.4 汉字结构

使用 BabelStone IDS，优先选择大陆 `G` 字形，以 IDS 的最外层描述符分类：

- `⿰`：左右结构。
- `⿲`：左中右结构。
- 其他明确结构：归入“其他结构”。

只判断汉字的最外层结构，不因内部部件含有 `⿰` 或 `⿲` 而判为左右类。结构只影响二、三根字的取码。

无 `G` 字形时，使用无地区标签的通用记录；仍无通用记录时，只有候选记录的左右分类一致才采用。先去除开头的 `〾` 变体标记，再判断结构。`〇` 等单根字不依赖结构，缺少 IDS 不影响其取码。

保留与其他 IDS 的结构分类分歧清单，供人工核对。缺失结构或无法确定适用字形时应明确报告；影响取码的疑问须确认后处理，不静默猜测。

### 2.5 简码

固定 B 简为单键上屏，映射如下：

| 字 | B 简 |
|---|---|
| 我 | `e` |
| 的 | `d` |
| 是 | `f` |
| 有 | `i` |
| 在 | `j` |
| 你 | `k` |

该映射固定，不参与退火优化。

AB 简给**全码为三码或四码**的字分配，取“全码首码＋一个 B 区键”。三码字与四码字一起按字频竞争，每个 AB 码位选一个字；B 区键为 `edfijk`。

配置使用现有码灵支持的 `rules = ["Aa"]`、`commit_keys = "edfijk"`、`code_num = 1` 和 `simple_assign_mode = "frequency"`，无需修改码灵 Rust 代码。固定 B 简所属级别的 `code_num = 0`，不额外分配其他单键简码；已有固定 B 简的六个字不再参与动态 AB 简分配。

本轮确认的简码只有固定 B 简和上述 AB 简，不另外增加空格简或其他级别简码。

### 2.6 词语编码

采用普通四定打法，取单字**全码**，不使用单字简码：

| 词长 | 取码规则 |
|---|---|
| 二字词 | 首字前二码＋末字前二码 |
| 三字词 | 首字首码＋次字首码＋末字前二码 |
| 四字及以上 | 首字、次字、第三字、末字各取首码 |

词编码脚本接受词库路径参数，暂不绑定词库。缺少单字全码的词会报错，不凭空补码；含简码的合并码表不能作为单字全码输入。

## 3. 算码字集与字频

使用 `prepare-inputs.sh` 默认生成的 `chars.txt`，即 **11,177 个简体、繁体常用字**。不改为 Unicode 基本区，也不缩为 8,105 个通规字。

字频沿用现有默认混合方式：

```text
USE_MIXED_FREQ=0.1
混合字频 = ceil(max(简体字频, 0.1 × 繁体字频))
```

简体、繁体字频分别来自 `charAbsoluteFrequencySC.json` 和 `charAbsoluteFrequencyTC.json`。缺失一侧字频按零处理。混合字频用于退火优化和 AB 简的按频分配。

拆分表沿用现有流程使用的大陆字形 `yustar_chaifen.dict.yaml`。

## 4. 优化目标与当前状态

以上方案设计已接入现有脚本框架，尚无经过正式退火优化的起步布局、测评结果或最终布局。

重码数、动态重码率、速度当量、键位热力的具体目标尚未设定。起步配置参考公共 `config.toml`，使用 4 线程、2,000,000 步，未启用目标偏差或硬上限；独立键位分布文件初始复制公共表，后续按灵云实测调整。

已验证默认 11,177 字的输入生成和取码：1,045 个三码字、10,132 个四码字，定义 368 个字根的 1,104 个编码分量。当前 IDS 数据下生成 163 个分类分歧记录，清单中的 `affects_code` 表示分歧是否影响二、三根字取码。

AB 简采用码灵原有出简资格，三码字与四码字均可参与按频分配，不增加全码长度限制。普通四定词规则已验证二、三、四字及长词和缺字报错。

## 5. 运行命令

以下命令都在 `moling/` 目录执行。结构数据默认来自 `~/home/IDS`，可以用 `IDS_ROOT` 指向另一份 Git 管理的 IDS 仓库。

```bash
# 只准备输入，同时生成结构分类和分歧清单
SCHEMA=lingyun ./prepare-inputs.sh

# 编译并启动摸底优化；默认重新准备输入
echo "灵云首次摸底" | SCHEMA=lingyun ./optimize.sh

# 指定 IDS 仓库
IDS_ROOT="$HOME/home/IDS" SCHEMA=lingyun ./prepare-inputs.sh

# 生成四定词码；词库每行为“词”或“词<TAB>频率”
./generate-lingyun-words-dict.pl \
  --codes /path/to/lingyun-full-codes.tsv \
  --words /path/to/words.txt > /path/to/lingyun-words.tsv
```

`--codes` 应指向该次布局的单字全码表，每行为 `字<TAB>全码`，可带频率列。词库不传 `--words` 时从标准输入读取。

# 魔卿算码优化

通用流程见 `HOWTO-OPTIMIZATION.md`。本文只记录魔卿当前有效的方案规则、验收目标、优化策略和起点。命令在 `moling/` 目录执行，方案变量为 `SCHEMA=moqing`。

## 1. 文件与不变量

| 用途 | 文件 |
|---|---|
| 退火配置 | `config-moqing.toml` |
| 键位分布 | `key_distribution-moqing.txt` |
| 优化输出 | `moqing-output/output-<时间戳>/` |
| 优化记录 | `MOQING-JOURNAL.md` |
| 正式宇浩方案 | `../../yuhao-assess-data/schemes/moqing.json` |

优化循环中只修改：

```text
config-moqing.toml
key_distribution-moqing.txt
```

以下输入保持不变：

```text
pair_equivalence.txt
字频、字根表、拆分表
prepare-inputs.sh 及其它输入生成脚本
```

Code Genie 内部指标只用于判断退火方向，最终验收一律使用正式宇浩测评结果。

## 2. 当前方案规则

魔卿是三码定长形码，字根双编码。当前大码、声码的可用集合分别定义如下：

- 大码 `A` 从排除 `a/e/u/o/z` 后的 21 个字母键中取值；`z` 不参与大码；
- 声码 `S` 从排除 `a/e/u/o/z` 后的 21 个字母键中取值；`z` 不参与声码；声母 `z`、`yi`、零声母以及「口」的声母 `k` 都不预设固定映射；
- `init.sh` 对魔卿设置 `OPTIMIZE_KEYS=0eizK`，由退火算法决定上述四类声码来源分别映射到哪个可用键；声码通常取字根读音的声母，其它无声母情况按当前输入规则处理；
- 单根字：`A1 S1 S1`；
- 双根字：`A1 A2 S2`；
- 多根字：`A1 A2 Az`；
- 最大码长为 3。

当前简码规则：

- 固定单键简码使用 `a/e/u/o`，映射以 `[fixed_simple_codes]` 为准；
- 一级动态简码：`A1[aeuo]`；
- **二级动态简码关闭**：`[[simple_levels]] level = 2` 的 `code_num = 0`；
- 当前只优化固定简码和一级动态简码，不优化 `A1A2[aeuo]`；
- 「一」不再固定使用简码 `Fi`，由退火算法按当前简码规则决定其简码；
- 正式方案的简码终止键为 `a/e/u/o/_`。

### 3.4 全码和全部简码键位热力

全码和简码热力都必须读取正式测评的 `測評結果.鍵位熱力.全碼.*` 与 `測評結果.鍵位熱力.簡碼.*`，不使用 Code Genie 的 `output-distribution.txt` 代替。`ceping.txt` 中的热力是原始值，不是总和为 1 的百分比；全码、简码分别把各自字段下的全部键位数值相加，再按下式计算目标键百分比：

```text
目标键热力 = 目标键原始热力 / 同一编码类别的全部键位热力总和 × 100%
```

分母包含对应类别下的全部实际键位，包括固定简码终止键和其它实际出现的键位。全码和全部简码中的以下六个键位都必须不超过 `3%`：

| 键位 | 全码测评字段 | 全码上限 | 简码测评字段 | 简码上限 |
|---|---|---:|---|---:|
| Q | `測評結果.鍵位熱力.全碼.q` | `<= 3%` | `測評結果.鍵位熱力.簡碼.q` | `<= 3%` |
| P | `測評結果.鍵位熱力.全碼.p` | `<= 3%` | `測評結果.鍵位熱力.簡碼.p` | `<= 3%` |
| Y | `測評結果.鍵位熱力.全碼.y` | `<= 3%` | `測評結果.鍵位熱力.簡碼.y` | `<= 3%` |
| B | `測評結果.鍵位熱力.全碼.b` | `<= 3%` | `測評結果.鍵位熱力.簡碼.b` | `<= 3%` |
| A | `測評結果.鍵位熱力.全碼.a` | `<= 3%` | `測評結果.鍵位熱力.簡碼.a` | `<= 3%` |
| C | `測評結果.鍵位熱力.全碼.c` | `<= 3%` | `測評結果.鍵位熱力.簡碼.c` | `<= 3%` |

总共验收 20 项：4 项动态选重率、4 项速度当量、6 项全码热力、6 项简码热力。判定不能只看 `summary.txt` 的综合得分第一名，必须逐线程检查正式宇浩数字。

## 4. 当前优化策略

### 4.1 优先级与全码权重完整性

1. 先优化知乎/北语全码和全部简码速度当量；
2. 全码动态选重率保持在 `3%` 以下，全部简码动态选重率保持在 `2%` 以下；
3. 在速度和重码率不明显退步的前提下，降低全码和全部简码 Q/P/Y/B/A/C 键位热力；
4. 只改一类因素，便于判断每轮变化的原因。

全码不是只优化当量的单目标。`[weights.full_code]` 的五项权重必须全部大于 `0`，并且总和为 `1.0`：

```text
collision_count > 0
collision_rate  > 0
equivalence     > 0
equiv_cv        > 0
distribution    > 0
```

因此不得为了追求速度当量把 `collision_rate` 或 `distribution` 设为 `0.00`。调整时从至少 `0.01` 起步，并相应从其它权重中扣除，保持五项权重总和为 `1.0`。全码重码、重码率、当量、当量变异系数和按键分布都必须保留优化梯度；Code Genie 的综合分可以体现优先级，但不能完全取消其中任何一类全码指标。

### 4.2 增量优化规则

只有出现可靠的近目标布局才使用 `--seed-keymap`。增量优化应根据起点的 Code Genie 内部指标设置略宽松的 `_max` 硬上限，使起点本身能够通过；这些硬上限只约束内部代理，不代替正式宇浩验收。

不在已证明冻结或方向错误的盆地中盲目增加步数。起步参数为 `threads = 8`、`total_steps = 8000000`；确认方向有效后再增加步数，最多不超过 `40000000`。

### 4.3 键位分布规则

`key_distribution-moqing.txt` 格式为：

```text
键位<TAB>目标百分比<TAB>用少了的惩罚<TAB>用多了的惩罚
```

四列必须是真实制表符分隔。该文件不是可有可无的手感参数，而是当前方案的按键热力起始约束。必须参考其中的起始设置，使实际热力总体保持期望的倒 T 形：`D/F` 与 `J/K` 为主要横杠，`E/I` 为上方重点键；`Q/P/T/Y/U` 尽量低，第三排 `X/C/V/B/N/M` 次低，其中 `B` 最低、`C` 低于其它第三排键。不得让全码实际分布长期大幅偏离这组目标后仍只用速度当量解释结果。

有一个设计例外：全码大码和声码都不使用 `a/e/u/o/z`，因此正式全码热力中的 `a/e/u/o/z` 为 `0` 是预期行为，不能把这些键的全码零热力判作分布失败；`a/e/u/o` 仍只在简码中使用，简码热力须单独按正式宇浩测评验收。`OPTIMIZE_KEYS=0eizK` 决定声母 `z`、`yi`、零声母和「口」的声母 `k` 的映射，不能预先假定它们落在哪些键上。

除上述 `a/e/u/o/z` 的全码例外外，必须同时检查 Code Genie 的全码 `output-distribution.txt` 和正式宇浩的全码/简码键位热力。键位分布只能约束键位边际频率，不能直接表达 A 码/S 码角色，也不能直接表达有方向的键对成本。因此任何键位分布调整都必须用正式宇浩热力和速度当量验证，不能只看内部分布偏差。

## 6. 标准命令

### 6.1 启动一轮优化

因声码规则已改变，当前规则的第一轮从随机键位布局开始，不指定种子：

```bash
echo "round-N: 一句话假设" | SCHEMA=moqing ./optimize.sh
```

只有在当前规则下产生可靠的近目标布局后，才可使用同一规则下的种子进行增量优化：

```bash
echo "round-N: 一句话假设" | SCHEMA=moqing ./optimize.sh \
  --seed-keymap moqing-output/output-<同规则输出时间戳>/thread-<序号>/output-keymap.txt
```

需要保留同一规则下的线程多样性时，改用：

```bash
echo "round-N: 一句话假设" | SCHEMA=moqing ./optimize.sh \
  --seed-dir moqing-output/output-<同规则输出时间戳>
```

### 6.2 生成单个线程的完整码表

```bash
SCHEMA=moqing NO_HTML=1 ./generate-root-chart.sh \
  moqing-output/output-<时间戳>/thread-<序号>
```

该命令使用线程目录的 `output-keymap.txt` 和对应 `source/` 输入，生成 `mabiao.tsv` 及相关字根、练习器文件。

### 6.3 测评单个线程

```bash
pnpm --dir "${YUHAO_ASSESS:-../../yuhao-assess}" exec tsx src/cli/index.ts \
  moqing-output/output-<时间戳>/thread-<序号>/mabiao.tsv \
  --scheme "${YUHAO_ASSESS_DATA:-../../yuhao-assess-data}/schemes/moqing.json" \
  --format table \
  --output moqing-output/output-<时间戳>/thread-<序号>/ceping.txt
```

使用 `pnpm --dir` 时，批量脚本应将码表、方案和输出路径转换为绝对路径，避免工作目录切换造成相对路径失效。

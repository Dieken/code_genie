# 魔卿算码优化

通用流程见 `HOWTO-OPTIMIZATION.md`。本文只记录魔卿当前有效的方案规则、验收目标、优化策略和起点。命令在 `moling/` 目录执行，方案变量为 `SCHEMA=moqing`。

## 1. 文件与不变量

| 用途 | 文件 |
|---|---|
| 退火配置 | `config-moqing.toml` |
| 键位分布 | `key_distribution-moqing.txt` |
| 优化输出 | `moqing-output/output-<时间戳>/` |
| 优化记录 | `MOQING-JOURNAL.md` |
| 正式宇浩方案 | `../../yuhao-assess-data/schemes/moqing.json` |

优化循环中只修改：

```text
config-moqing.toml
key_distribution-moqing.txt
```

以下输入保持不变：

```text
pair_equivalence.txt
字频、字根表、拆分表
prepare-inputs.sh 及其它输入生成脚本
```

Code Genie 内部指标只用于判断退火方向，最终验收一律使用正式宇浩测评结果。

## 2. 当前方案规则

魔卿是三码定长形码，字根双编码：

- 大码 `A` 和声码 `S` 都从排除 `a/e/i/o/z` 后的 21 个字母键中取值；`z` 不参与大码；
- 声码取字根读音的声母，无声母时取 `v`；
- 单根字：`A1 S1 S1`；
- 双根字：`A1 A2 S2`；
- 多根字：`A1 A2 Az`；
- 最大码长为 3。

当前简码规则：

- 固定单键简码使用 `a/e/i/o`，映射以 `[fixed_simple_codes]` 为准；
- 一级动态简码：`A1[aeio]`；
- **二级动态简码关闭**：`[[simple_levels]] level = 2` 的 `code_num = 0`；
- 当前只优化固定简码和一级动态简码，不优化 `A1A2[aeio]`；
- 正式方案的简码终止键为 `a/e/i/o/_`。

## 3. 当前正式验收目标

每个线程都必须生成完整 `mabiao.tsv`，并使用正式方案 `../../yuhao-assess-data/schemes/moqing.json` 测评。实际值等于目标也算达标。

### 3.1 全码动态选重率

读取频率降序字段，不使用“原序”字段：

| 指标 | 目标字段 | 上限 |
|---|---|---:|
| 知乎全码动态选重率 | `測評結果.動態選重分析.知乎簡體動態選重率.全碼` | `<= 2%` |
| 北语全码动态选重率 | `測評結果.動態選重分析.北語簡體動態選重率.全碼` | `<= 2%` |

### 3.2 全部简码动态选重率

| 指标 | 目标字段 | 上限 |
|---|---|---:|
| 知乎全部简码动态选重率 | `測評結果.動態選重分析.知乎簡體動態選重率.簡碼` | `<= 1%` |
| 北语全部简码动态选重率 | `測評結果.動態選重分析.北語簡體動態選重率.簡碼` | `<= 1%` |

### 3.3 速度当量

| 指标 | 目标字段 | 上限 |
|---|---|---:|
| 知乎全码速度当量 | `測評結果.速度當量分析.知乎簡體字頻全碼速度當量` | `<= 1.26` |
| 北语全码速度当量 | `測評結果.速度當量分析.北語簡體字頻全碼速度當量` | `<= 1.26` |
| 知乎全部简码速度当量 | `測評結果.速度當量分析.知乎簡體字頻全部簡碼速度當量` | `<= 1.29` |
| 北语全部简码速度当量 | `測評結果.速度當量分析.北語簡體字頻全部簡碼速度當量` | `<= 1.29` |

### 3.4 全部简码键位热力

热力必须读取正式测评的 `測評結果.鍵位熱力.簡碼.*`，不使用 Code Genie 的 `output-distribution.txt` 代替。`ceping.txt` 中的简码热力是原始值，不是总和为 1 的百分比；先把全部 `測評結果.鍵位熱力.簡碼.*` 数值相加，再按下式计算目标键的百分比：

```text
目标键简码热力 = 目标键原始热力 / 全部简码键热力总和 × 100%
```

其中分母包含 `簡碼` 下的全部键位，包括固定简码终止键和其它实际出现的键位。判定使用归一化后的 Q/P/Y/B/A 百分比：

| 键位 | 测评字段 | 上限 |
|---|---|---:|
| Q | `測評結果.鍵位熱力.簡碼.q` | `<= 3%` |
| P | `測評結果.鍵位熱力.簡碼.p` | `<= 3%` |
| Y | `測評結果.鍵位熱力.簡碼.y` | `<= 3%` |
| B | `測評結果.鍵位熱力.簡碼.b` | `<= 3%` |
| A | `測評結果.鍵位熱力.簡碼.a` | `<= 3%` |

总共验收 13 项：4 项动态选重率、4 项速度当量、5 项简码热力。判定不能只看 `summary.txt` 的综合得分第一名，必须逐线程检查正式宇浩数字。

## 4. 当前优化策略

### 4.1 优先级

1. 先优化知乎/北语全码和全部简码速度当量；
2. 全码动态选重率保持在 `2%` 以下，全部简码动态选重率保持在 `1%` 以下；
3. 在速度和重码率不明显退步的前提下，降低 Q/P/Y/B/A 简码热力；
4. 只改一类因素，便于判断每轮变化的原因。

### 4.2 增量优化规则

只有出现可靠的近目标布局才使用 `--seed-keymap`。增量优化应根据起点的 Code Genie 内部指标设置略宽松的 `_max` 硬上限，使起点本身能够通过；这些硬上限只约束内部代理，不代替正式宇浩验收。

不在已证明冻结或方向错误的盆地中盲目增加步数。起步参数为 `threads = 8`、`total_steps = 8000000`；确认方向有效后再增加步数，最多不超过 `40000000`。

### 4.3 键位分布规则

`key_distribution-moqing.txt` 格式为：

```text
键位<TAB>目标百分比<TAB>用少了的惩罚<TAB>用多了的惩罚
```

四列必须是真实制表符分隔。大码不使用 `z`。默认热力偏好遵循 `HOWTO-OPTIMIZATION.md` 的倒 T 原则，但在速度当量和动态重码率未稳定前，不为了手感牺牲主要指标。

键位分布只能约束键位边际频率，不能直接表达 A 码/S 码角色，也不能直接表达有方向的键对成本。因此任何键位分布调整都必须用正式宇浩热力和速度当量验证。

## 6. 标准命令

### 6.1 启动一轮优化

```bash
echo "round-N: 一句话假设" | SCHEMA=moqing ./optimize.sh \
  --seed-keymap moqing-output/output-20261018-155903/thread-02/output-keymap.txt
```

未指定种子时会从随机键位起步；`--seed-keymap` 与 `--seed-dir` 互斥。

### 6.2 生成单个线程的完整码表

```bash
SCHEMA=moqing NO_HTML=1 ./generate-root-chart.sh \
  moqing-output/output-<时间戳>/thread-<序号>
```

该命令使用线程目录的 `output-keymap.txt` 和对应 `source/` 输入，生成 `mabiao.tsv` 及相关字根、练习器文件。

### 6.3 测评单个线程

```bash
pnpm --dir "${YUHAO_ASSESS:-../../yuhao-assess}" exec tsx src/cli/index.ts \
  moqing-output/output-<时间戳>/thread-<序号>/mabiao.tsv \
  --scheme "${YUHAO_ASSESS_DATA:-../../yuhao-assess-data}/schemes/moqing.json" \
  --format table \
  --output moqing-output/output-<时间戳>/thread-<序号>/ceping.txt
```

使用 `pnpm --dir` 时，批量脚本应将码表、方案和输出路径转换为绝对路径，避免工作目录切换造成相对路径失效。
